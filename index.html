01

关于

在国产 EDA 工具链这条不算宽的路上

复旦大学微电子学院本硕，现在在成都做逻辑仿真器研发。负责的是 GLS 中的 X 态语义与相应的左移验证；再往外一圈， RTL 级仿真里的 XProp、SDC，门级仿真里的 SDF 反标、时序检查、 X 态悲观去除，都是我持续在跟的方向。此前在上海做数字前端 EDA 工具研发， 也是从那时起接触编译器与仿真器这条线，是 ArkCompiler 的内部贡献者。

具体一点说：我关心 X 在仿真器里到底该怎么被解释 —— 一条 X 从哪来、沿哪条路径传播、 在什么条件下应该被收敛成确定值，以及在时序检查里遇到 X 时该报、该放还是该降级。 这件事的标准是含糊的：IEEE 定义了四值逻辑，却没有定义悲观与乐观的边界， 工具之间口径也不一致。往上游走一步，就是左移验证 —— 能不能在门级仿真之前，就把这些 X 相关的隐患暴露出来，而不是等 sign-off 才发现。

这块工作在签核流程里的位置比较特殊 —— DFT 扫描链、低功耗上电序列、X 传播、异步路径这些场景， 静态时序分析覆盖不到，必须让门级网表带真实延迟跑一遍。它不会产生最漂亮的性能数字， 但它是 sign-off 前的最后一道关。

这个站点用来放我的技术笔记。EDA 领域有大量问题在公开资料里几乎找不到答案， 标准含糊、工具行为不一致、只能自己踩。踩完记一笔，算是给自己留档，也欢迎同行来对。

04

领域知识

踩过的坑、定过的规则，以及整理成册的讲义与译本

X 态语义与 SDC 约束

持续更新

RTL 侧是 XProp 的乐观与悲观策略之争，门级侧则叠加了未初始化寄存器、多驱动冲突、 亚稳态，以及 SDF 反标本身引入的不确定性；再加上同一份 SDC 在静态分析里被当作约束、 在仿真里被当作检查判据，两边读出的语义并不完全一致。这些问题的共同点是 —— 查文档解决不了。

门级时序检查与 SDF 反标

持续更新

setup / hold / recovery / removal / pulse-width 五类检查，加上反标的覆盖范围与工艺角口径。 核心问题只有一个：什么条件下该报违例、什么条件下不该报。标准在这里留了太多解释空间， 工具默认行为又不一致，只能靠真实设计一遍遍对出来。

X 态悲观去除的判定规则

梳理中

X 在时序检查里的角色很尴尬：既可能是真实的不定态，也可能只是建模过度悲观带来的幻影。 哪些 X 可以安全地当作 don't-care 收敛掉、哪些必须显式报出，业界至今没有统一标准。 这里需要的是可判定的规则，而不是经验主义的默契。
