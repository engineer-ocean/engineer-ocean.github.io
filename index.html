01

关于

在国产 EDA 工具链这条不算宽的路上

复旦大学微电子学院本硕，现在在成都做逻辑仿真器研发。负责的是 GLS 中的 X 态语义与相应的左移验证；再往外一圈， RTL 级仿真里的 XProp、SDC，门级仿真里的 SDF 反标、时序检查、 X 态悲观去除，都是我持续在跟的方向。此前在上海做数字前端 EDA 工具研发， 也是从那时起接触编译器与仿真器这条线，是 ArkCompiler 的内部贡献者。

具体一点说：我关心 X 在仿真器里到底该怎么被解释 —— 一条 X 从哪来、沿哪条路径传播、 在什么条件下应该被收敛成确定值，以及在时序检查里遇到 X 时该报、该放还是该降级。 这件事的标准是含糊的：IEEE 定义了四值逻辑，却没有定义悲观与乐观的边界， 工具之间口径也不一致。往上游走一步，就是左移验证 —— 能不能在门级仿真之前，就把这些 X 相关的隐患暴露出来，而不是等 sign-off 才发现。

这块工作在签核流程里的位置比较特殊 —— DFT 扫描链、低功耗上电序列、X 传播、异步路径这些场景， 静态时序分析覆盖不到，必须让门级网表带真实延迟跑一遍。它不会产生最漂亮的性能数字， 但它是 sign-off 前的最后一道关。

这个站点用来放整理成册的地图、讲义与译本。EDA 领域有大量问题在公开资料里几乎找不到答案， 标准含糊、工具行为不一致、只能自己踩。踩完记一笔，算是给自己留档，也欢迎同行来对。

02

专注方向

两个互相咬合的领域，不是并列的两条线

01 / 门级仿真

SDF 反标、时序检查与 X 态悲观去除

门级仿真的 SDF 反标，setup / hold / recovery / removal / pulse-width 检查， 以及 X 态悲观去除（X-pessimism removal）。关注在真实工艺角下， 门级仿真给出的违例与静态分析为什么会对不上。

  • GLS
  • SDF
  • STA
  • X-pessimism
02 / RTL 仿真

XProp 与 SDC 语义

RTL 级仿真中的 X 态传播规则与 SDC 约束语义。X 从哪来、往哪去、 遇到不确定分支时该走悲观还是乐观 —— 门级网表的 X 来源比 RTL 复杂得多， 但两套规则必须能对上，否则前后端会各说各话。

  • XProp
  • SDC
  • RTL
  • Verilog

知识地图

以「造验证工具的人」为主体视角画的一张七层全景图：硬基础、仿真内核、验证方法学与工具族、 工程基础设施、前沿方向、产业与生态，直到非技术能力，共 62 个模块。 每层都标了能力自评与补全路径，并附一份只收「会被反复查第二遍」的资源清单。 放在这一章最前面，是因为它更像坐标系 —— 先看清自己站在哪一层，再决定往哪一层补。
